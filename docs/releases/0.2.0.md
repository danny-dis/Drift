# Drift 0.2.0

Drift is a local-first AI organism/workbench: a small browser interface and Python
service with persistent folders, bounded background work, and explicit controls.
It is not a clinical ADHD tool, diagnosis, treatment, or a substitute for care.

## Release contents

- An installable Python wheel and source distribution, versioned together with
  the frontend at **0.2.0**.
- Built frontend HTML, JavaScript, CSS, and default configuration included in
  both Python artifacts. An installed service does not need Node.js or a source
  checkout to serve its interface.
- A standalone frontend ZIP and `SHA256SUMS` alongside the Python artifacts.
  The ZIP is static UI output, not a standalone inference server.
- Regression coverage and installed-wheel checks on Ubuntu and Windows with
  Python 3.12 and 3.13. Tag releases are gated on the entire matrix, production
  frontend builds, and clean installed-package checks.

## Thought capture and reliability

- Save exact originals before inference; input can be messy, repeated, interrupted,
  or long (up to 1,000,000 characters per capture). Explicit retry IDs prevent
  duplicate saves, while separate intentional captures remain separate.
- Recover browser drafts, keep newer text safe during pending saves, search saved
  originals, and inspect advisory summaries separately from canonical text.
- Resume bounded background staging after restart. Failed task checkpoints do not
  publish ghost tasks or false completion. Recognized credentials are filtered
  from inference using the complete original before splitting into parts.
- Retry temporary inference connection/rate-limit/server failures at most once.
  Each physical call consumes the persisted call and task allowance; exhausted
  retries require review. Background planning does not retry on every idle cycle.
- Thought organization and retained-source research do not request unnecessary
  tools. Research uses bounded valid evidence packets and checks citation quotes
  against retained originals. This is provenance checking, not fact verification.
- The active dashboard includes a detailed high-DPI isometric office with calm
  defaults, opt-in motion, reduced-motion support and truthful runtime status.

## Install and run

Use Python 3.12 or newer. Download the wheel from the GitHub release, verify its
SHA-256 against `SHA256SUMS`, and install into a virtual environment:

```sh
python -m venv .venv
# POSIX: source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install ./drift-0.2.0-py3-none-any.whl
python -m drift.main --host 127.0.0.1 --port 47116 --box ./my-drift-box --name drift
```

Open `http://127.0.0.1:47116`. Keep the bind address local unless you understand
and have secured remote access. Back up your organism folders before upgrading.
The wheel includes defaults and public UI files, not your memories, `.env`, API
keys, or private organism folders. Dependencies still need to be installed by
pip; this is not a bundled offline Python installer.

## Inference and privacy boundaries

An inference provider must be configured separately. The bundled defaults target
a separately running local DMR-X endpoint at `http://127.0.0.1:47113/v1`; Drift
does not install or start that gateway. Provider/model availability, free-tier
capacity, credentials, network access, and upstream uptime remain external
requirements. A successful package smoke test proves configuration loading and
UI serving, **not** live inference availability. Free-only settings are not a
promise of unlimited free inference or guaranteed uptime.

Use environment variables for provider credentials; never put real credentials
in a release configuration. A local-first interface does not imply local-only
inference: selected remote providers receive the content sent to them. Review
provider settings and privacy controls before submitting sensitive material.

## Build the release from source

Maintainers need Node.js 22 and Python 3.12+. From the repository root:

```sh
python -m pip install -e '.[test]' build
cd frontend
npm ci
npm run build
cd ..
python -m pytest -p no:cacheprovider -q
python -m drift.release_build
python -m build
python -m drift.release_build --smoke dist/drift-0.2.0-py3-none-any.whl --expect-version 0.2.0
python -m drift.release_build --assets dist --expect-version 0.2.0
```

Resource preparation is required before building from a checkout. It replaces
`drift/resources/` with validated release inputs. It rejects non-empty credential
fields, credentials embedded in URLs, symlinks, hidden frontend files, source
maps, and unexpected frontend file types. It does not read `.env` or organism
state. Review the public frontend bundle as part of release review; these checks
are not a general-purpose secret scanner.

## Publication and rollback

Pushing a matching `v0.2.0` tag triggers release automation. It requires no PyPI
credentials or repository secrets; publication uses the workflow's scoped GitHub
token. All four CI matrix combinations must pass before the publishing job can
start. That job rebuilds and smoke-tests the artifacts, creates a draft with all
assets, verifies the uploaded asset names, then publishes and verifies the
result. A failed upload or verification leaves only a draft, not a public partial
release. A rerun encountering an existing draft must be investigated rather than
silently overwriting published assets.

This release does not publish to PyPI. Do not claim release publication or green
hosted CI until the actual tagged workflow has completed successfully.

For rollback, stop Drift, back up the organism folders, and reinstall a previously
verified wheel in a fresh virtual environment. Retain your folder backup: package
rollback alone does not reverse application data changes.
